# GitHub 发布准备

## 当前整理结果

- 保留源码、构建脚本、Gradle Wrapper、Room schema、v7a JNI 库和第三方许可。
- `artifacts/` 日志与截图、`参考布局/` 图片只保留在本机，不再跟踪。历史文档中的相关路径是本地证据索引。
- 忽略本机 SDK、工具缓存、环境配置、签名材料和常见临时文件。
- 移除预置 NAS 地址、设备序列号与 README 中的固定本机路径。NAS 测试改为显式传入地址，TV 测试显式选择设备。
- 原有未跟踪文档 `docs/NYQOVA-局域网发现闪退修复建议.md` 保留原样，暂不纳入发布包。

## 项目许可证

维护者已选择 Apache-2.0。根目录 `LICENSE` 为许可证原文，`NOTICE` 为项目声明；README 与贡献说明同步采用该许可。Apache-2.0 允许商业使用、修改和分发，不包含“仅个人使用”或“禁止盈利”的限制。

第三方组件继续遵循原有许可证。FFmpeg 的 LGPL、MACLib 与图标等许可必须分别保留并遵守。

## 历史与干净源码包

本地 Git 历史的规则扫描发现旧 NAS 地址、设备序列号和本机路径，分布于历史源码、脚本、README 和构建日志。扫描未发现所检查的常见令牌、私钥及硬编码密码模式；规则扫描不能保证不存在其他敏感内容。

从当前跟踪范围删除文件不会从历史提交删除内容。首次公开建议使用导出的干净源码包，在另一目录初始化新的 Git 仓库；原项目与历史留在本地。**不要直接推送当前仓库的全部历史。** 这是因为历史中已确认包含本机标识，而非构建需要。

运行：

```powershell
.\scripts\export-source.ps1
```

输出 `artifacts/NYQOVA-source.zip` 和 `artifacts/NYQOVA-source.sha256`，仅包含当前 Git 跟踪且不被忽略的文件，以及明确列入脚本的新增发布文件。使用工作区最新内容，不含 `.git/` 和提交历史。脚本不会自动包含其他未跟踪文件；新增源码应先纳入 Git 或调整发布清单。

解压到新目录后确认文件与许可，执行：

```powershell
git init -b main
git add .
git diff --cached --stat
git commit -m "Initial public source release"
```

在 GitHub 创建空仓库，随后使用 GitHub 提供的仓库地址添加远程并推送。不要复用原目录执行这段初始化流程。当前整理不会创建远程仓库或上传文件。

## 正式发布前

1. 核对 `LICENSE`、`NOTICE` 与第三方声明完整，并重新导出源码包。
2. 在干净解压目录中验证 README 的构建步骤。
3. 按第三方声明核对发行材料，特别是 FFmpeg 静态链接的源码和重链接材料。
4. APK 用 GitHub Release 单独分发，保管正式签名；不要把密钥、密码和调试日志上传。
