# 0.4.0：快速建库与后台补全

本版同时交付已确认的 D1–D6、T1–T5（见 [菜单与焦点](tv-0.3.2.md)），并纳入后来确认的扫描优化。0.3.2 是代码检查点，最终安装包为 0.4.0。

## 扫描行为

- 第一阶段只遍历 NAS 目录、解析 CUE 和匹配 LRC，不逐首读取音频标签或下载封面。每个文件夹提交一次，已入库歌曲立即可查询和播放，CUE 对应整轨不重复入库。
- 第二阶段独立补全标签、时长与封面。音乐库查询与扫描使用不同线程；文件指纹未变化则复用已完成结果。补全可能调整歌曲名称、歌手、专辑归类及专辑数量。
- 混合歌曲目录不把任意一张目录图片套到所有专辑。目录封面需符合单文件、单专辑 CUE 或专辑名称匹配条件；其他歌曲使用各自内嵌封面或在线匹配，并清理旧的错误目录封面引用。
- 音乐库上方显示当前阶段和剩余待办，可暂停或继续。用户已选择曲目时不持续重建列表，返回分类或刷新可读取最新信息，完成后保留原位置更新。
- 未完成遍历和标签待办保存在设备；重新进入 App 自动继续。Activity 重建不会销毁正在进行的进程内任务；不保证系统终止进程后仍在后台执行。
- 只有完整遍历成功才清理已经移除的目录与文件。断网或暂停保留已提交批次和未访问的旧目录。单文件失败最多尝试两次，连续网络读取失败时暂停，可手动重试。
- WebDAV 标签读取使用有界 Range、请求超时和单文件读取预算。播放数据源维持原配置。SMB、NAS 凭据隔离、只读访问和 CUE 稳定歌曲 ID 均保留。
- 数据库通过 3→4 迁移增加持久待办，不清空歌曲、收藏、歌单或连接设置。

## 实测与复现

当前 NAS 首次快速索引：约 **5 秒、1,351 首逻辑歌曲、16 个目录批次**；初始待补全 1,255 个音频文件。目录基本归类完成后，后台标签会继续细分实际专辑。未变化目录再次扫描约 **2 秒**。这些数据仅代表本次 NAS 与网络环境，歌曲数量按当前支持格式和 CUE 分轨计算。

构建与检查：

```powershell
./scripts/build.ps1 -UseMirror -IncludeDeviceTests -TestRunner com.nyqova.app.TvInstrumentation
./scripts/test-tv-ui.ps1 -Phases scan,main,resume,interaction,menus
```

验证涵盖分批写入、独立补全和暂停、待办跨进程恢复、分页/搜索/收藏/歌单、真实 NAS 播放与歌词、CUE/队列冷启动恢复，以及菜单、焦点、清空确认和播放中自动进入播放页。

报告保存在 `artifacts/tv-0.4.0-*.txt`，首次扫描记录为 `tv-0.4.0-initial-index.txt`。APK 为 `artifacts/NYQOVA-0.4.0-v7a-debug.apk`。
