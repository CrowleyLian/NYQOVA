# 0.6.1：局域网发现 ANR 与歌词候选自动显示

## 局域网发现

用户提供的 E900V20D 现场报告指出 NsdManager.init 在 mdnsd 未就绪时无限等待。源码核对确认：旧版 SourceDiscovery 的属性初始化在调用方主线程执行 getSystemService(NSD_SERVICE)，与报告堆栈吻合。本次未连接该盒子，未独立读取其 ANR/固件文件。

- 构造器不再访问 NSD；初始化、发现注册、解析和停止发现全部进入独立的串行后台通道。
- 初始化 1.5 秒后仍未返回时，本次发现不再接纳该初始化结果。不能依靠 interruption 强行停止固件内部等待，因此全进程最多一个 NSD 通道、一项初始化在途，队列有界；再次打开发现会继续独立探测。
- 阻塞初始化任务只持有应用上下文、取消标记和发现对象弱引用，避免持续持有已关闭窗口。
- 保留原有私有 IPv4 /24 的 SMB/WebDAV 端口探测。ConnectivityManager 查询、TCP 连接和 OPTIONS 请求均在另一组后台线程执行，不等待 NSD。
- 整轮最长 20 秒，仅完成一次。关闭或页面销毁会取消回调、关闭正在连接的 socket、取消 HTTP 请求并清空排队工作；NSD 清理也不在主线程执行。
- 音乐源窗口由 Activity 管理生命周期，父窗口关闭会关闭发现窗口；重复打开先取消旧会话。窗口采用现有主题。

没有执行或写入 setprop/启动系统服务逻辑。也没有采用需要 NAS 端配套响应器的自定义 UDP 广播端口；现有端口探测本身即可在系统 NSD 不可用时独立工作。

## 歌词

- 保留已匹配录音版本的优先级。没有完全匹配但存在候选时，自动选择有序候选列表中的第一条，立即返回歌词文档；不存在候选时仍显示未找到，不生成歌词内容。
- 主播放页和全屏歌词页使用同一结果，支持同步歌词和纯文本歌词。自动选择会在全屏歌词来源信息中标明可更换版本。
- 缓存同时保存已选版本、候选列表（最多 20 项，确保包含已选项）和自动选择标记。缓存写入失败不影响本次显示。
- 在全屏歌词 → 更多 → 选择版本可改选；手动版本覆盖自动选择并持久保存，候选列表仍保留。手动搜索结果映射回原歌曲时也保留候选。
- 兼容旧缓存。保留本地 LRC、简体显示、提供方设置和取消机制。
